# 구현 노트 (1단계: 전투 코어)

기획서 v6 의 4장(전투)·5장(능력치) 중 1단계에 필요한 부분을 `sim/` 에 Python 참조 구현으로 옮겼다.
수치는 전부 `data/db.json` 에서 읽는다. 아래 "임시 규칙"은 기획서에 값이 없어 구현하면서 정한 것이며, 시뮬레이션으로 조정한다.

## 구현된 것

- 공격 판정 흐름(4-3): 명중 → 치명타 → 즉사(몬스터→플레이어만) → 피해 계산 → 방어막 흡수 → 상태이상·부위 손상
- 쿨타임 스킬(4-9): 쿨타임 N = 사용 후 N라운드 동안 사용 불가, 0 = 제한 없음. 영혼력 일부 회복, 행동 횟수(민첩성, 상한 3)
- 기본 스킬 4종 + 몬스터 전용 스킬 7종, 상태이상 3종(독·출혈·기절, 부여 확률 지원), 부위 손상과 장비 내구도
- 인간형 NPC 전투불능, 동료(아군 여러 명, 적은 생존 아군에게 균등 무작위)
- 몬스터 등급 공식(5-6/6-1), 구울·고블린 개별 보정, 사냥 숙련 보너스(상대 한정)
- 정책: `highest_value`(4-10 자동 플레이, 플레이어 기본), `attack_only`(몬스터 기본), `guard_when_hurt`, `random`
- 몬스터마다 `skills` 와 `ai` 를 DB 에서 지정(4-9 "쿨타임이 끝난 스킬 중에서 고른다")

## 구현하며 정한 임시 규칙 (기획서에 없음)

| 항목 | 정한 값 | 비고 |
|---|---|---|
| 영혼력 스케일 | 영혼력 스탯 × 10 = 최대 영혼력 | 종족 표 값(2~4)이 너무 작아 스킬 비용을 정수로 쓰기 위함 |
| 영혼력 회복 | 라운드 종료 시 +2 (+영혼 재생력 × 1) | 4-9 "일부만 회복" |
| 방어막 지속 | 사용자의 다음 턴 시작까지 | 기획서에 지속 규정 없음 |
| 행동 횟수 | 라운드마다 민첩성 × 0.2 를 누적, 정수 부분만큼 추가 행동 | 상한 3. 구울(민첩성 3)은 약 1.6회/라운드 |
| 쿨타임 0 | 같은 라운드에 여러 번 사용 가능 | 추가 행동을 가진 몬스터가 의미를 가지려면 필요 |
| 명중·치명 | 명중 기본 0.90(0.50~0.97), 치명 기본 0.05(상한 0.5), 배율 1.5(상한 2.5) | |
| 피해 | 스킬 위력 × (1 + 근력 × 0.1) × 치명배율 × (1 − 물리내성 × 0.02, 경감 상한 60%) | 5-6 "방어 경감 = 물리내성" |
| 자연재생 | 최대 생명력의 0.5% × 자연재생 | 출혈 중에는 절반 |
| 즉사 | (9 − 등급) × 0.2% + 원거리 1%, 상한 5% | 9등급 근접은 0 |
| 부위 손상 | 명중 시 15%, 내구도 손실 2 | 팔 −3 명중률, 다리 −3 유연성, 몸통 −3 자연재생 |
| 상태이상 | 독·출혈 중첩당 2 피해(중첩 상한 5), 독내성 1당 −5%(최소 20%), 인내심 1당 기절 −5%(최대 75%) | |
| 몬스터 영혼력 | 기본 4(= 최대 40) | 4 이상이면 영혼력이 병목이 되지 않음(아래 참고) |
| 플레이어 기본 스킬 | 베기·강타·방어·관통 4종만 | 몬스터 전용 스킬은 플레이어가 쓰지 않는다 |
| 타 종족 | 종족 비교 시 바바리안 성인식 방어구 키트를 동일 지급 | |

## 몬스터 스킬 설계안 [임시]

**원칙**
- 기획서 6-1 의 "서사적 근거 없이 속도·등급을 올리지 않는다"를 지켜, 능력치(근력·물리내성·재생·민첩성)는 등급 공식과 기획서의 개별 보정(구울, 고블린 검사/궁수)만 쓴다. 몬스터 차이는 **스킬 세트**로 만든다.
- 스킬은 이름에서 자연스럽게 떠오르는 범위에서만 붙였다. 마스터 설정 근거가 있는 것이 아니므로 확정이 아니다.
- 몬스터는 기본적으로 쓸 수 있는 가장 센 공격을 쓴다(`attack_only`). 방패병류만 생명력이 절반 아래로 떨어지면 방어 스킬을 우선한다(`guard_when_hurt`).

**스킬표** (영혼력 비용 / 쿨타임)

| 스킬 | 위력 | 비용/쿨 | 부가 효과 | 쓰는 몬스터 |
|---|---|---|---|---|
| 물어뜯기 | 10 | 4/1 | 출혈 | 칼날늑대, 늑대, 호랑이 |
| 찢기 | 24 | 5/1 | — | 구울, 엘더구울 |
| 사격 | 10 | 3/0 | — | 고블린 궁수, 스켈레톤 궁수 |
| 조준 사격 | 18 | 8/3 | — | 고블린 궁수, 스켈레톤 궁수 |
| 방패 밀치기 | 8 | 6/3 | 30% 기절 | 코볼트 방패병 |
| 영혼탄 | 14 | 6/1 | — | 스켈레톤 마법사 |
| 통곡 | 6 | 5/2 | 25% 기절 | 벤시 |
| (기존) 베기·강타·방어·관통 | | | | 나머지 |

**몬스터별 세트**: 노움·고블린·타락한 노움은 베기만(가장 약한 기준선). 고블린 검사=관통+베기, 스켈레톤 전사=베기+방어, 데스핀드=강타+관통+베기, 스톤골렘·곰=강타+베기, 호랑이=강타+물어뜯기+베기.

**설계하며 발견한 것**
- 몬스터 영혼력이 2(=20)이면 비싼 스킬을 몇 번 쓰고 바닥나서, 구울의 "빠른 행동"(추가 행동)이 거의 쓰이지 않는다. 영혼력 4 이상에서 결과가 같아지므로(포화) 기본값을 4로 했다. 4-2 에서 "영혼력이 행동 횟수를 결정하던 구조"를 폐기했으므로 몬스터 영혼력을 넉넉히 두는 것은 규칙과 모순되지 않는다.
- 쿨타임 0 스킬을 라운드당 한 번만 쓰게 하면 민첩성 추가 행동이 헛돈다. 그래서 쿨타임 0 은 제한 없음으로 했다.

## 시뮬레이션 결과 (바바리안·대검, 숙련 0, n=3000)

| 구분 | 몬스터 | 승률 | 승리 시 남은 HP | 비고 |
|---|---|---|---|---|
| 1층 | 노움·고블린 | 99.9% | 74 | 기준선 |
| 1층 | 칼날늑대 | 97.8% | 62 | 출혈 |
| 1층 | **구울** | **82.5%** | **38** | 1층 유일의 위협 |
| 2층 | 고블린 검사/궁수 | 94% | 52 / 63 | 궁수는 즉사 3.7% |
| 2층 | 스켈레톤 전사·코볼트 방패병·벤시·타락한 노움 | 99% | 69~74 | |
| 2층 | 엘더구울 | 79.8% | 36 | |
| 2층 | 스톤골렘·곰 | 90.8% | 44 | |
| 2층 | 스켈레톤 궁수 | 93.5% | 61 | 즉사 4.5% (가장 높음) |
| 2층 | **데스핀드·호랑이(6등급)** | **64% / 69%** | 28 / 36 | 가장 위험 |

- 구울은 숙련 0→2단계에서 82.5% → 91.2% 로 오른다(+9%p, `attack_only` 정책으로 측정 — 아래 정책 부작용 때문). "숙련으로도 쉽게 극복되지 않는다"에는 부합하지만 효과가 약간 큰 편이다.
- 약한 무기에서는 구울이 확실한 관문이 된다(기본 정책 기준): 창 76%, 둔기 66%, 검 54%, 방패 41%, 활 33%.
- **정책 부작용**: 기획서 4-10 의 자동 정책(값이 가장 높은 스킬 우선)에서 방어는 방어막 두께(8 + 물리내성 × 2)로 값을 매기므로, 물리내성이 높은 빌드(방패, 숙련)는 공격 대신 방어를 먼저 쓰게 된다. 방패 바바리안이 구울 상대로 41%(기본 정책) vs 63%(`attack_only`)로 갈린다. 자동전투 정책의 "값" 정의를 다시 정해야 한다.
- 엘더구울(7등급)에 구울의 민첩성 3 을 주지 않았다. 구울 계열의 속도는 마스터 설정 확인이 필요하다(6-2 의 [미정]과 같은 종류).

## 종족 비교 (이전 결과, 몬스터 스킬 도입 전)

- 요정이 가장 강하게 나온다(영혼력 스케일 때문). 기획서 3-2 는 요정이 가장 취약하다고 했으므로 영혼력 스케일과 비용표 재조정 후 종족 비교를 다시 해야 한다.
- 드워프의 방어 특화가 약하다(물리내성 +4 = 경감 8%).

# 브라우저 프로토타입 (`web/`)

한 판 루프를 휴대폰 브라우저에서 직접 플레이해 보기 위한 프로토타입. 규칙은 Python 참조 구현(`sim/`)을 JS 로 옮겼고(`web/src/combat.js` 등),
`web/tests/parity.js` 가 같은 조합의 승률을 두 구현에서 비교해 통계적 일치를 확인한다(10개 조합, 오차 3.5%p 이내).

## 구조 (확장 지점)

| 파일 | 역할 | 확장할 때 |
|---|---|---|
| `src/combat.js` | 전투 규칙(판정·쿨타임·상태이상·정책). 상태는 순수 JSON | 정수 스킬, 새 상태이상(마비·동상 등), 새 정책 |
| `src/entities.js` | 전투 참가자 생성 | 새 종족(잠긴 4종), 동료 |
| `src/world.js` | 지형 생성·구역·조우·보상 | 2층, 암흑지역, 고블린 덫, 약초 |
| `src/game.js` | 상태 머신(화면 전환·저장·시계) | 생존 수치, 밤친구, 상점 |
| `src/ui.js` | DOM·캔버스 | 화면 추가 |
| `data/db.json` | 모든 고정값 | 수치 조정은 코드 수정 없이 여기서 |

게임 상태 `G` 는 JSON 으로 그대로 저장되며 전투 도중 상태(난수 포함)까지 복원된다(2-2). 규칙 코드는 DOM 을 모르므로 Node 에서 테스트되고, 나중에 GML 로 옮길 때 그대로 기준 구현이 된다.

## UI 스타일 (스톤샤드 스타일 참고)

스톤샤드 스크린샷 두 장(소지품·캐릭터 창, 하단 HUD)을 참고해 **구성과 분위기**를 모바일 세로 화면에 맞게 다시 만들었다. 이미지·아이콘·글꼴 파일은 가져오지 않았고, 아이콘(`web/src/icons.js`)과 장식(아치 부조, 프레임)은 직접 그린 SVG/CSS 다. 상용 출시 전에 원작 설정 권리와 함께 UI 유사성도 점검한다(부록 B-⑧).

| 참고한 점 | 구현 |
|---|---|
| 보랏빛 도는 어두운 석재 창, 제목판 + 닫기(X) 버튼, 위쪽 고딕 아치 부조 | `.win` 컴포넌트(`win()`), `DS.archBand()` |

# 전투 방식 변경: 지도 위 턴제 (스톤샤드식)

스크린샷(적이 지도에 서 있고 여러 마리가 함께 있는 장면, "Enemy!" 표시, 칸을 가리키는 조준 표시)을 참고해 **별도 전투 화면을 없애고 지도 위에서 바로 싸우는 방식**으로 바꿨다.
결정은 사용자 확인: ① **이동 한 칸 = 한 턴, 이동할 때마다 스킬·공격 재사용 대기 1 회복** ② **적은 지도에 미리 보임** ③ **여러 마리 동시 전투**.

## 규칙 (`web/src/tactics.js`, 수치는 `data/db.json`)

| 항목 | 구현 |
|---|---|
| 턴 | 플레이어가 한 번 행동(이동 1칸 / 스킬 / 대기)하면 한 턴. 그 뒤 모든 적이 한 번씩 행동하고, 턴 종료 처리(상태이상 피해·자연재생·영혼력 회복·재사용 대기 −1)가 일어난다 |
| 재사용 대기 | N턴 = 사용 후 N턴 동안 사용 불가, 0 = 제한 없음. **전투 밖에서 걸어도 줄어든다** |
| 적 배치 | 구역마다 무리(1~3마리)를 고정 시드로 배치(같은 세계는 항상 같은 자리). 1층 기준 약 15마리. 걸음당 확률 조우는 없어졌다 |
| 적 AI | 시야(6칸, 벽에 막히면 못 봄)에 들어오면 경계("적!") → 사거리에 닿으면 가장 센 공격, 아니면 최단 경로로 접근. 시야에서 사라지고 6턴이 지나면 경계 해제. 방패병류는 다치면 방어 우선 |
| 행동 횟수 | 민첩성이 높은 적은 한 턴에 여러 번 행동(이동 포함) — 구울이 빨리 붙는다 |
| 사거리 | 사거리 1 = 상하좌우 인접만(대각선 불가). 2 이상은 직선거리 + 시선. 무기가 정한다: 창 2, 활 5, 나머지 1. 몬스터 원거리 스킬은 자체 사거리(사격 5, 영혼탄 4, 통곡 3) |
| 공격 | 스킬 칸을 누르면 사거리 안 적이 하나일 땐 바로 사용, 여럿이면 노란 조준 표시가 뜨고 대상을 탭. 적을 바로 탭하면 기본 공격(베기), 멀면 다가감. 적이 있는 칸으로 이동해도 기본 공격 |
| 자동 이동 | 지도 탭 이동은 적이 경계 중이거나 맞으면 멈춘다(한 걸음씩) |
| 전투 종료 | 경계 중인 적이 없으면 손상 부위가 회복된다(4-8 "전투가 끝날 때까지") |
| 사망 | 생명력 0 (헤드샷 즉사는 이전과 동일). 판정 함수(명중·치명·피해·상태이상·부위 손상·숙련)는 `combat.js` 를 그대로 재사용 |

## 이전 방식과 달라진 점 / 사라진 것

- 별도 전투 화면, **걸음마다 확률 조우**, **순차 무리 전투**(7-1 "몬스터 무리": 체류가 길수록 마릿수 증가)는 없어졌다. 시간이 갈수록 위험해지는 장치(무리 증가)는 아직 대체하지 않았다.
- **자동전투와 예상 승률**(4-10)은 빠졌다. 지도 위 전투에서는 모의 전투를 같은 방식으로 돌릴 수 없어 다시 설계해야 한다.
- 영혼력은 전투 시작마다 가득 채우지 않고 **턴마다 +2** 회복한다. 생명력도 걸음마다 자연재생한다(1% 걸음 회복 규칙은 폐지).
- Python 시뮬레이터(`sim/`)는 **1대1 라운드 전투 기준 구현**으로 남았다. 판정 규칙의 기준과 밸런스 비교에는 아직 유효하지만, 위치·접근·동시 전투는 반영하지 못한다. JS 쪽 `parity.js` 도 이 1대1 코어를 비교한다.

## 기획서에 반영해야 할 것 (확인 후 수정)

- 1-5·16장 "맵 이동은 실시간, 전투는 턴제 전투 화면" → **맵 이동도 턴제(1칸=1턴), 전투는 지도 위**. 부록 A 의 "엔진·구조" 결정도 함께.
- 4장: 라운드 단위 쿨타임 → **턴 단위**(이동 포함), 행동 횟수 규칙, 사거리·시선·위치, 동시 전투, 적 AI(경계·접근).
- 7-1: 조우 규칙(확률 조우 → 지도에 배치된 적), 무리 규칙, 암흑지역과 시야.
- 4-10: 자동전투 재설계. 시간 압박(미궁 시계)은 현실 시간 그대로 유지했다.

## 밸런스 메모 (미검증)

- 1대1 기준으로 맞춘 수치라서, 지도 위에서는 접근 거리 덕분에 원거리 무기(활)가 크게 유리해질 수 있고, 여러 마리가 한꺼번에 붙으면 훨씬 위험해진다. 플레이 후 조정이 필요하다.
