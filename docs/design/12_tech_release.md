## 15. 스킬 확장과 저장

- **스킬 확장**: 덱 빌딩이 폐기되었으므로, 스킬을 어떻게 **얻고 해금**하느냐가 성장의 핵심이 된다(레벨·장비·정수 등). 정수의 전용 스킬은 쿨타임 스킬 목록에 그대로 합류하는 것으로 추정.
- **정령술 / 원소 속성**(요정과 연결, 확정 아님): NPC 대화에서 정령술 스킬 계열과 원소 속성(불 등, 희귀도 서열) 존재가 확인됨. 이능이 정령술의 대상일 가능성이 있으나 미확정. 소환에는 지속 시간과 회복 시간이 있어, 영혼력과는 다른 별도 자원 관리일 수 있다.
- **저장/불러오기**(여러 저장 슬롯 등)는 설계가 아직 없다.

## 16. 2D 구현과 출시

- **2D 탑다운**으로 처음부터 만든다. **맵 이동도 턴제(한 칸 = 한 턴)이고 전투는 별도 화면 없이 지도 위에서 한다** [확정, v7]. 쿨타임은 턴 단위다(이동 포함). 미궁 시계는 턴과 별개로 현실 시간 기준이다.
- **맵 이동·몬스터 배치**: 7장의 "선택지마다 전투 확률 표시" 구상은 폐기했다. 칸 단위 턴제 이동 + 지도에 배치된 적(4-12, 7-1)으로 대체한다. [v7]
- **조작은 모바일 터치 기준**: 지도 탭 이동(경로 자동 이동, 적이 경계 중이면 한 걸음씩), 화면 방향 버튼(누르고 있으면 계속 이동), 하단 스킬 핫바(번호 키는 PC 보조). 꾹 눌러도 글자 선택·길게 누르기 메뉴가 뜨지 않게 한다. [v7]
- **UI 방향** [v7]: 어두운 석재 창 스타일 — 제목판과 아치 부조가 있는 창(소지품: 장비칸 + 칸 단위 가방 + 아이템 툴팁 / 캐릭터: 능력치 + 부위별 체력 인체 도식), 하단의 체력·영혼력 바와 번호 핫바(비용·재사용 대기 표시), 색깔 전투 로그, 횃불이 비추는 만큼만 보이는 시야. 외부 게임의 이미지·아이콘·글꼴은 쓰지 않고 직접 제작하며, 출시 전에 권리·유사성을 점검한다(부록 B-⑧).
- **서버 없이 오프라인 싱글**로 출시한다. 랭킹·클라우드 저장·결제 검증이 필요해지면 출시 후에 검토한다.
- 2D 맵이 구현된 뒤에야 의미가 생기는 요소: 시각·시야 능력치, 원거리 사정거리, 범위 효과(반경 기반 아이템), 나침반, 넉백.
- **지형 스케일**: 1층은 서쪽 끝에서 중심까지 걸어서 하루 넘게 걸리는 규모이고, 2층은 이동 거리에 따라 위험이 달라지는 거리 감각이 있다. 이를 바탕으로 좌표-시간 환산 기준을 잡는다.
- **모바일 앱 스토어 출시**가 최종 목표다. 세로 화면에서도 스킬 목록 방식이 자연스럽게 적용되도록 설계했다.
- **GameMaker 구현 방향** [확정]: 게임 로직(턴·쿨타임·전투 계산·정수·생존 수치)은 object 이벤트 밖의 script/struct에 두고, 종족·몬스터·스킬 등 모든 고정값은 DB(`dungeon_stone.db` → `db.json`)에서 읽고 코드에 하드코딩하지 않는다. 저장은 전체 상태를 JSON으로 직렬화해 전투 도중 상태까지 복원한다(2-2). 앱 출시 빌드는 상업 라이선스와 플랫폼 요건(iOS는 Mac 필요)을 착수 전에 확인한다.
- 앞으로 새로 만드는 모든 콘텐츠는 "무엇이 일어나는가"를 위치·화면과 분리해 설계해, 임시 그래픽을 나중에 아트로 바꿀 때 표현만 바꾸면 되게 한다. 안개·실제 이동 시간 같은 개념은 맵 구현 단계에서 설계한다(미리 흉내 내지 않는다).
